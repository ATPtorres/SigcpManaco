SIGCP MANACO · Instalación y mantenimiento

Manual técnico

Volver al sistema · Imprimible con Ctrl + P. No contiene contraseñas.

1. Arquitectura

Frontend HTML/CSS/JavaScript sin compilación. API Express sobre Node 22 o superior y MySQL 8.4 relacional con transacciones. MySQL es la fuente de datos; el navegador recibe una proyección de lectura.

  • server/app.cjs: rutas, sesión, seguridad, recursos públicos y auditoría.
  • server/service.cjs: reglas de fabricación, inventario, horas, calidad y programación.
  • server/state.cjs: estado compacto para la interfaz.
  • server/images.cjs: galería, validación, subidas y asignación por modelo/color.
  • server/planning.cjs: recomendación de plazo con tiempos de ficha y supuestos explícitos.
  • database/: esquema y migraciones aditivas registradas por versión.
  • tests/: integración MySQL e interfaz real con Playwright y axe.

2. Arranque local Windows

cd /d "C:\xampp\htdocs\SIGCP manaco"
iniciar.cmd

La instalación local usa MySQL 8.4 en 127.0.0.1:3307 y Node en el puerto 3000. MariaDB de XAMPP permanece separada. El supervisor recupera el backend tras una caída, registra errores en JSON y crea una copia diaria mientras está activo. Estado: .runtime/supervisor-status.json. Diagnóstico: .runtime/backend.log y backend-error.log.

3. Instalación y actualización

npm ci
npm run db:migrate
npm run db:seed
npm run images:assign
npm run start:supervised

Configura .env con credenciales propias, HOST, PORT, conexión MySQL y APP_TIME_ZONE. No publiques .env ni .runtime. El usuario inicial solo se crea si no existe; editar APP_PASSWORD no cambia una contraseña existente. Para restablecerla utiliza el procedimiento del README principal.

4. Datos y reglas

Modelo → variante por talla/color → ficha versionada → etapas y receta. Una orden congela su ficha y requerimientos. Movimientos por lote y ubicación determinan existencias; las reservas reducen disponibilidad. La cantidad aceptada de una etapa define entrada y consumo de la siguiente. Las unidades rechazadas son descartes; no se recuperan implícitamente.

PRODUCTO_CALZADO y MODELO_CALZADO conservan imagen_url. DETALLE_ORDEN_ETAPA guarda fechas programadas y reales. Cambiar el código visible mantiene las claves y referencias. Modificar el plazo exige motivo, control de concurrencia y confirmación para plazos cortos. La programación de etapas debe estar dentro de la orden y respetar la secuencia. Las fechas reales se generan al ejecutar las operaciones y no se inventan para datos heredados.

5. Imágenes

Los WebP de la galería están en assets/shoes; sus originales de alta resolución se conservan en assets/shoes/source. catalog.json registra nombre, color y prompt. Se crearon mediante la herramienta integrada de imágenes y se revisaron visualmente. La API publica solo imágenes con extensiones y rutas permitidas.

Las subidas aceptan PNG/JPEG/WebP, firma de archivo y límite de 2 MB. Solo Administrador puede subir imágenes. Los nombres son aleatorios y se guardan en assets/uploads, excluido de Git. Al trasladar o restaurar el sistema, copia también assets/uploads: las exportaciones JSON no incluyen esos archivos binarios.

6. Seguridad y auditoría

Contraseñas con scrypt y sesiones con tokens almacenados como hash. Cookie HttpOnly y SameSite Strict. Consultas parametrizadas, validación de entradas y perfiles comprobados en el servidor. La auditoría conserva actor, entidad, destino, cambios saneados y motivo, excluyendo contraseñas y tokens. La visibilidad del formulario solo afecta a la contraseña recién escrita; no recupera las claves existentes.

7. API

GET  /api/state?compact=1
GET  /api/records/:type?page=1&limit=25&q=texto
POST /api/images
PUT  /api/orders/:id/plan
PUT  /api/order-stages/:id/plan
POST /api/order-stages/:id/start
POST /api/order-stages/:id/finish

Los errores se entregan como JSON con mensaje legible. Los filtros usan parámetros y tipos de registro permitidos. La respuesta incluye identificador de solicitud para diagnóstico.

8. Respaldo

npm run db:backup:daily
npm run db:backup -- backups/copia-negocio.json
npm run db:restore -- --database base_alternativa --file backups/copia-negocio.json --apply

La copia diaria usa SHA-256. La restauración requiere otra base vacía y no reemplaza registros existentes. El JSON de negocio excluye usuarios y sesiones. Conserva también una copia SQL completa según README.md y una copia externa de imágenes propias. No borres mysql-data para reiniciar el servicio.

9. Pruebas y publicación

npm test
npm run test:interface
npm audit --audit-level=high

Usa una base distinta de DB_NAME cuyo nombre termine en _test. npm test recrea sus tablas. Ejecuta las suites en secuencia. Chromium se instala con npx playwright install chromium. GitHub Actions prepara MySQL aislado y ejecuta auditoría y ambas suites.

Para publicar instala dominio y certificados y adapta deploy/nginx.conf.example. Configura APP_ORIGIN, COOKIE_SECURE=true y TRUST_PROXY=loopback, y mantén Node limitado a loopback. MySQL debe usar privilegios mínimos y TLS si es remoto. La plantilla no publica el sitio ni emite certificados automáticamente.
